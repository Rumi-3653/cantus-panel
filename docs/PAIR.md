# 兩台工作站，一張工作圖

介面以 M4（控制端）與 M1（工作端）標示兩個角色。實際不限定硬體型號，但需要 Node.js 24、自己的來源設定與已登入的 Codex CLI。預設關閉，不會搜尋或連接其他主機。

## 自行準備連線

本 repo 不建立 SSH、隧道或遠端帳號。先自行建立受控的加密轉送：控制端的某個 **loopback 埠** 通往工作端 `127.0.0.1:4589`。兩邊服務都只監聽 loopback，不可把未登入保護的 API 直接公開。

在控制端不追蹤的 `config/local.json` 中，保留自己的來源設定，增加以下欄位：

```json
{
  "pairRole": "controller",
  "pairPort": 4592
}
```

`4592` 只是範例，換成你自行建立的本機轉送埠。只接受整數埠，不接受來自瀏覽器的任意主機地址。

在工作端自己的 `config/local.json` 中，保留來源與 CLI 設定，增加 `"pairRole": "worker"`。

兩台都以明確啟用的方式啟動：

```bash
CANTUS_MODE=local CANTUS_ENABLE_EXECUTION=1 npm start
```

若只想先看圖，控制端可以不設定 `CANTUS_ENABLE_EXECUTION`，派工維持關閉。自己的 HTTPS 登入入口仍然只接控制端；它會轉送已授權的第二台工作區操作。

## 使用

1. 控制端打開 Lineage，顯示 M4、M1 的工作與既有明確關係。名稱相同也以主機及 ID 分開。
2. 選擇 M4 工作，按「派給 M1」，填入任務及 **M1 上已存在的絕對工作目錄**。
3. 按「確認派給 M1」後，M1 建立自己的 Codex 子對話；合圖保留父子連線與派工收據。重新讀取可查看狀態及回覆，點子工作可回到 M1 的 Work 頁面。

任務只包含你在表單寫的內容，不會自動拷貝原對話、來源檔案或憑證。需要的專案必須已在 M1 可用。原生權限批准仍保留，不提供跨機無限制權限。

同一派工編號不會建立兩次；逾時或重新啟動後只查收據，不自動重送。未知結果仍標示未知。回合完成不等於工作驗收。

合圖中的原始關係只供查看；要編輯單台的關係或標記，切換成「目前工作區」。對話可用右鍵「重新命名」及「移至資料夾」整理；這些名稱與資料夾只存在 Cantus，不更動原始對話或磁碟目錄。

## 資料邊界

- 控制端：`state/pair/` 保存跨機關係與派工收據。
- 工作端：`state/dispatch-receipts/` 與 `state/managed/` 保存獨立執行紀錄。
- 每台各自：`state/lineage/` 保存自己的顯示名稱、資料夾與關係。

這些目錄與 `config/local.json` 全部排除 Git。請不要提交真實地址、帳密、轉送腳本、對話或工作目錄快照。
